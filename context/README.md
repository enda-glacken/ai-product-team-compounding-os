# Product brain

Durable, reviewed knowledge the whole team (and its agents) can build on: users, domain, system behaviour, and how the team works. One file per topic.

Each entry carries:

```markdown
## <Claim>
- **Evidence:** <project/evidence IDs>
- **Confidence:** high / medium / low
- **Reasoning:** why we believe it; what we rejected and why
- **Approved by:** <name>, <date> · **Re-check by:** <date or trigger>
- **Supersedes:** <earlier entry, if any>
```

Entries arrive through capture-learnings → human review → context-maintenance. Repetition is not evidence: a proposal doesn't become knowledge because it's been said often. When something is wrong, supersede it; keep the old reasoning visible.

See [examples/brightdesk/context](../examples/brightdesk/context/) for real-looking entries.
