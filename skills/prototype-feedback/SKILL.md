# Prototype feedback

**Inputs:** the question being tested; the prototype revision; notes or recordings you're allowed to use.
**Writes to:** `evidence.md`, and proposed edits to `spec.md`.

## Steps
1. Restate the question the prototype was meant to answer.
2. Record only what was actually observed, with the conditions (who, how many, which revision, which task).
3. Put interpretations and hypotheses in separate rows from observations. Don't copy raw private notes; summarise and reference.
4. Say what the prototype cannot tell you (scale, production data, real latency, edge cases nobody hit).
5. Propose spec edits, or a first spec draft if none exists.

## Output
Evidence-linked findings. A prototype session is never treated as validation or as an approved requirement.
